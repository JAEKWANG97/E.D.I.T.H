# API Contract Review Rules

## Compatibility

- Response field names consumed by another service or frontend must remain
  stable unless the caller is changed in the same merge request.
- Request payload fields added for richer context should be additive and optional
  unless all callers are migrated.
- Preserve current response fields used by Java clients: `review`, `summary`,
  and `techStacks`.

## Error and Fallback Behavior

- Failed AI review generation should return a predictable failure or fallback
  shape instead of causing unpacking or deserialization errors.
- JSON responses generated by an LLM should be parsed defensively because model
  output can include code fences or explanatory text.

## Review Focus

- Check whether DTO, controller, or inter-service client changes break existing
  serialized field names.
- Check whether fallback paths still match the documented API shape.
